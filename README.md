# Azur Promilia SDK Repair

面向 Apple Silicon Mac 的 CrossOver 转译《蓝色星原：旅谣》的SDK 兼容工具。它调用官方 SDK 处理登录、协议、安全验证（人机验证）与回调，通过原生 AppKit 控件显示界面。普通协议链接交给本机默认浏览器；合理把验证结果回传给原生SDK验证。

## 当前范围与限制

- 已实测：几乎还原黄鸡原生sdk窗口和完美修复登录等sdk界面的问题
- 保留官方 SDK 控件数据、文本、资源与交互流程。macOS 字体回退与 Windows 字体的字形存在差异，不承诺逐像素一致。
- FineWine 模块固定为 3.1.2，匹配 CrossOver 26.3.0（本机实测 26.3.0.39832）。SDK 和浏览器文件校验值见 `dependencies.lock.json`。
- 游戏内 Vuplex 控件兼容暂未修复，游戏中的网页仍可能空白或触发 Vuplex 子进程错误。此限制与 SDK 协议链接的默认浏览器跳转是两条流程。
- 安装后直接使用 CrossOver 原容器中的官方游戏启动项启动即可。
- 当前版本要求游戏位于所选容器的 `drive_c` 内，暂不支持外部游戏盘映射。
- 不包含 CrossOver、游戏或官方 SDK 二进制，需要用户自行安装。应用与磁盘图标使用用户提供的图片，其权利归原权利人，不包含在本项目的 GPL 代码授权内；其余 SDK 界面资源在本机运行时读取。

## 从源码构建 DMG

需要 Apple Silicon Mac、macOS 15 或更新系统、带 Swift 6.2 或更新编译器的 Xcode，以及 Zig。本次使用 Xcode 27.2 / Swift 6.4 和 Zig 0.16.0 验证。运行游戏还需要可用的 CrossOver、Rosetta 2 和已安装的官方启动器及游戏。

1. 下载或克隆完整仓库，保留 `ThirdParty/FineWine`。
2. 安装 Zig 0.16.0，使 `zig` 能在 PATH 中找到；也可以设置环境变量 `ZIG` 指向它的可执行文件。
3. 用 Xcode 打开 `AzurSDKRepair.xcodeproj`，在顶部选择共享方案 **构建DMG**，执行 Product → Build，或按 **⌘B**。
4. 首次构建从 GitHub 下载并校验固定版本 FineWine 模块，需要网络。之后可以使用 `Build/Cache` 中已通过校验的缓存。
5. 安装包输出到 `Build/Products/蓝原SDK修复-0.1.0.dmg`，附带 SHA-256 校验文件。

终端也可执行：

```sh
./Scripts/build.sh
```

Xcode 的构建方案调用同一个脚本。该脚本编译原生界面、安装工具和 Windows 桥接组件，执行本地 ad-hoc 代码签名校验，然后使用系统 `hdiutil` 生成 DMG。无付费开发者账号要求；本地 ad-hoc 签名只满足可执行文件的本机代码签名要求，不代表经过审核。通过互联网下载的应用可能受到 Gatekeeper 限制；请确认来源和校验值，使用系统设置中允许打开该应用的操作。

运行维护检查：

```sh
./Scripts/test.sh
```

正常及阻塞清理路径的 Windows 回归检查可以执行 `./Scripts/test-shutdown.sh /实际路径/CrossOver.app 容器名称`。

## 安装给其他用户

1. 通过 CrossOver 安装官方游戏启动器并下载好游戏。退出该容器内的游戏、启动器和其他程序。
2. 打开 DMG，把「蓝原SDK修复.app」拖进 Applications，然后打开。
3. 选择本机 CrossOver 应用、游戏容器和包含 `AzurPromilia.exe` 的游戏目录。
4. 点击「安装修复」。工具会先校验版本与文件，备份容器配置及官方 SDK，再创建一份独立 CrossOver 运行库副本，并写入该容器的运行库路径。原 CrossOver 应用保持不变；同一容器中的程序会共用所选运行库。
5. 直接在 CrossOver 原容器中启动官方启动器，正常启动游戏即可。工具会备份并接入该容器原有启动脚本，也会接入能识别的现有 macOS 快捷方式；工具里的「打开游戏启动器」也可使用，为快捷打开方式。
6. 首次运行按照官方流程需要阅读相应条款协议、登录。

运行库、配置和官方文件备份位于用户目录 `Library/Application Support/CrossOver/AzurSDKRepair`。本机提取的 SDK 界面资源位于所选容器 `drive_c/FineWine/native-assets 。`

## 启动、更新与恢复

官方启动器运行和游戏退出时，受本工具管理的 SDK 与浏览器入口会恢复为官方原文件，供启动器检查和更新。游戏进程出现时，监视器短暂暂停进程，验证本机文件，再接入桥接组件。未验证的新 SDK 会停止该次游戏启动，不覆盖新版本。

更新游戏或 CrossOver 前建议退出游戏，在本工具中「恢复原配置」。完成官方更新后，再使用匹配版本的修复工具安装。不要把整个游戏或 SDK 固定为旧版来绕过版本保护。

卸载时先退出游戏与启动器，打开本工具点击「恢复原配置」。它会恢复备份的容器配置、官方组件和已接入的原快捷方式及容器启动脚本，删除独立运行库。恢复成功后再删除本工具应用。恢复容器配置采用安装前的完整备份，安装后手动改过的容器设置需要重新设置。

修复工具不默认删除官方登录和协议记录，避免让普通安装/恢复影响账号使用。分享问题日志前请自行检查敏感信息；不要提交容器、账号缓存、`drive_c/FineWine`、本机配置或游戏文件。
